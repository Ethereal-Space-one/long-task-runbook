# 一次离线接手演练

这个练习只回答一件事：新会话有没有接对候选、复用对证据，并停在用户指定的位置？它不是 Skill 的运行依赖，也不进入安装包。需要 Python 3.8+ 和 Git，不需要第三方包、模型账号或网络。

## 先验证评测器

从仓库根目录运行：

```sh
python3 evals/recovery.py selftest
```

它会在临时目录创建真实但虚构的 Git 工作副本，运行 6 条应通过的示范轨迹、8 条应拒绝的反例，并清理临时文件。反例包括发布较大的旧稿、重复检查、盲写、未经回读就推进、抄用旧计数、漏写检查点、草稿阶段启动下一项目及超时后重发。**这些是对评测器的控制实验，不是模型通过率。**

## 给一个新会话做题

```sh
lab=$(mktemp -d)
python3 evals/recovery.py prepare port "$lab/attempt"
# 在 "$lab/attempt" 启动全新会话；把 REQUEST.md 的内容作为本轮用户请求。
# 会话结束后，由评审者在本仓库运行：
python3 evals/recovery.py grade port "$lab/attempt"
```

每次另建尚不存在的子目录；Git 工作副本含绝对定位信息，不要搬动。执行者只看练习目录（测试 Skill 时另提供指定版本），不要给它本目录的控制器、答案或上轮轨迹。把 `port` 换为下表中的名称可切换题目；准备和评分须使用同一名称。练习中的发布和启动动作只写入该练习目录。

| 场景 | 需要分辨的证据 |
| --- | --- |
| `port` | 两个工作副本和互相冲突的交接记录；当前版只缺打包检查，还没有提交。 |
| `matched` | 上次提交未收到响应，但原始回执与当前候选、资产完全一致。 |
| `wrong-check` | 资产摘要正确，成功检查却属于另一提交。 |
| `draft` | 同一提交和资产，发布记录仍是草稿。 |
| `wrong-asset` | 源与检查一致，已发布资产的摘要却不符。 |
| `unconfirmed` | 上次响应丢失，现有发布记录也无法确认。 |

评分看模拟工位的调用顺序和读取结果，并核对最终发布对象、下一项目标记、真实工作副本和写回的检查点；退出码 0 表示通过。没有合格回执却继续、事后把记录改漂亮，都不能抵消已经发生的错误动作。这里以 `desk.py` 记录操作；额外的只读 Git 命令不会被计分。这是合作式练习，不是防篡改沙箱。

如需比较 Skill 效果，在两份相同的全新练习里使用相同请求、模型、推理配置及工具权限，一组明确加载固定版本的 Skill 和对应参考，另一组不提供该 Skill。分别保留工具轨迹与评分；发现了某个同名 Skill 不代表加载了目标版本。一对结果只描述这两次运行；若要评价普遍改善，还需更多重复与未见场景。
