# 任务拆分与指派

## 定义任务包

以用户可验收的成果作为任务包终点。把可以连续完成的同类事项放在一个包内。遇到输入切换、独立验收、真实依赖或授权变化时再拆包。任务很短或项目已有同等手顺时，直接沿用现有记录。

从用户要求中确定哪些是硬性条件，哪些由执行者决定。只列真正影响后续执行的依赖。尚无可靠分母时，先登记候选集合及核实办法，待盘点后更新实际范围。并行执行时按实际写入目录或交付物划分责任，跨任务的共享文件由明确的执行者管理。

多执行者之间交回时，记录交付版本、接收者和原执行者的停写状态。接收者核对当前文件后接管写入或合并。发现交付后又有变更时，先核对变化和当前责任人。

## 项目中需要可找到的记录

| 记录 | 保存内容 |
| --- | --- |
| 接手入口 | 当前执行位置、权威检查点与任务清单的位置、首次需要阅读的项目规范 |
| 任务清单 | 稳定任务标识、范围、前置条件、验收条件、负责人和状态。任务多时记录成员集合及未纳入项 |
| 当前检查点 | 当前授权、任务与停止点、工作位置、输入版本、完成与未完成项、原件位置、下一动作 |
| 证据和验收 | 实际交付物、验证结果、审查发现及返修复检。保留可核对的文件、版本、行号、命令或外部操作回执 |

这些记录可以合在现有项目文件中。当前状态有一个权威入口，其他位置引用。将执行位置从筹备目录迁到工作副本时，更新接手入口指向新位置，并在新位置保存恢复检查点。

## 可复制任务 Prompt

将括号内的内容替换成当前任务。已有任务卡时，发送其路径及本轮变化即可。

```text
请执行「任务 ID 和名称」。

先读「接手入口」和其中指向的当前检查点。以「已授权范围」和「固定输入版本」为本包依据。工作位置是「路径、分支或对象」。写入范围是「目录或交付物」，共享内容由「责任人」处理。

按「实际依赖和内部批次」推进。交付「成果清单」，按「验收条件与验证方法」核对。既有成果从原始验收证据恢复，按实际变化补做受影响工作。遇到局部阻断，登记具体项并完成其余可做范围。

交回时提供实际位置、交付物、原始证据、检查结果、未完成项和下一动作。更新同一个检查点，到「停止点」交回。
```

验收交回时可只发任务 ID、执行入口、证据链接和需要决定的事项。若用户已指定审核者，由其依据冻结结果审查。执行者可自行修复的普通问题留在同一包内。
