# 任务拆分与指派

任务包的终点是一个能单独验收的结果，不是一次会话或若干小时。小改动用一句话就够。例如：「把帮助页的 `--out` 改成 `--output`，对照当前 CLI 帮助核实，只交回文档差异。」不为此另建台账。

## 划定本包

- **授权和停止点**：写清用户这次要的是计划、实施、复核还是发布，以及做到哪里交回。任务卡记录约定，不产生授权。「已验证」是状态，不是下一阶段的许可。若后续阶段已获授权且条件满足，则直接继续。
- **成果和边界**：列出要交付什么、哪些不做、怎样判定完成。批量任务写明本批成员；总数未核实时，保留候选清单，不拿估计数计算完成率。
- **拆批和停写**：只在实际依赖、验收方式、写入责任或授权发生变化时拆包。同包内可先做一小批，写明什么结果允许扩大、什么情况要停。不因分了批就逐批等批示。并行时按文件或产物分工，共享项指明唯一写入者；交接时交回候选版本，原负责人停写后再接管。
- **回退**：可能覆盖数据或放大错误时，先确认本批会改哪些对象、失败后能从哪里恢复。优先在副本或单独的输出目录试做。回退仅涉及本包改动，不重置共享工作区；无法安全回退且风险未经同意时，执行前交回风险与选项。回退方案不授权新的外部操作。

## 留下可复核的版本

复用项目已有的任务卡、检查点和检查日志即可，当前状态只设一个入口。接手入口指向**当前工作位置**和相应原件；迁移工作副本时一起更新指向。

| 记录 | 另一位执行者应能回答的问题 |
| --- | --- |
| 任务 ID、输入和候选版本 | 我接手的是哪份内容？给出提交、不可变快照或可复原的补丁与基线；有相关未提交、未跟踪的输入时也要能定位，仅记分支或 `HEAD` 不够。 |
| 验证回执 | 对哪个候选、哪些对象，用什么命令或人工标准，在什么必要条件下核对？实际看到了什么，原始输出或审查记录在哪？未运行、失败、部分通过分开写。 |
| 下一动作和停止点 | 由谁从哪一步接续、还缺哪项验收？局部失败只阻断依赖它的部分。若有回退或外部操作，写实际状态，不把计划当结果。 |

返修后不要把旧回执改标为新版本。候选内容、相关输入或依赖、验证环境或验收标准有变化时，先定位受影响的结论，再补验；无关结果可以引用原件并说明为何仍适用。范围说不清就扩大检查。恢复时如何处理冲突或结果不明，见[状态恢复与复核](recovery-and-review.md)。

## 可复制的指派

已有任务卡时，只发任务 ID、入口和本轮变化。没有任务卡时，可按需删减下面的提示：

```text
任务「ID」：请交付「结果」。按本次指派可做「范围」，到「停止点」交回。
从「入口、输入版本」开始；写入「对象」，不动「排除项」。
用「方法」确认「能观察到的结果」。若分批：先做「成员」，仅在「条件」满足后扩大。
交回「候选版本、验证回执、缺口、下一动作」。若失败，按「可安全回退或停止的位置」处理。
```

## 示例：只试两页（虚构）

用户只授权迁移指南 A、B 的链接，本地检查后交回；其余 18 篇不动。在单独副本改这两页，给不可变的候选快照编号。任务卡只需留下结论和原件位置：

- **快照 S1**：站内链接检查器逐条核对目标；A 为 3/3，B 为 1/2，失败项指向已改名的页面。逐条结果在 `checks/S1.txt`。这是部分通过，不是迁移完成。
- **快照 S2**：仅修正 B 中那条路径，检查器、目标页面及 A 均未变。重查 B 为 2/2（`checks/S2-B.txt`）；A 引用 S1 的回执，注明复用理由。不把 S1 的报告改写成 S2 的全量检查。
- **交回**：两页通过后停止，不扩到其余 18 篇。若放弃试点，保留原稿和验证记录，不采用副本即可。
